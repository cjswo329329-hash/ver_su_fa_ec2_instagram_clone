# 안전 코드 수정 하네스 (Safe Refactor Harness)

코드를 수정할 때 반드시 아래 절차를 순서대로 밟습니다.

## 실행 절차

### 1. 사전 테스트 (Baseline)
- 코드 수정 전 `npm run test` (또는 프로젝트 테스트 명령어)를 먼저 실행하여 현재 상태를 확인합니다.
- 이미 실패 중인 테스트가 있으면 사용자에게 알리고 기준점을 확정합니다.

### 2. 범위 격리 & 계획
- **기본 원칙**: 단일 에이전트가 하나의 관심사/모듈에 집중하여 작업합니다.
- **서브에이전트 병렬 실행 판단 기준**:
  - **허용 조건**: ① 사용자가 명시적으로 병렬 처리를 요청했거나, ② 상호 의존성이 전혀 없는 2개 이상의 독립 디렉토리/도메인 작업일 때만 허용합니다.
  - **금지 조건**: 공통 모듈(`shared`, 전역 `types`), 패키지 설정, 또는 모듈 간 상호 참조/의존성이 있는 경우 **반드시 단일 에이전트**로 순차 진행합니다.
  - **병렬 작업 규칙**: 각 서브에이전트는 배정된 독립 디렉토리 내 파일만 수정하며, 모듈 단위 검증만 개별 수행합니다.
- 3개 이상 파일이 변경되는 구조적 수정은 `implementation_plan.md`를 작성하여 계획(서브에이전트 사용 여부 포함)을 승인받은 뒤 진행합니다.

### 3. 구현
- 승인된 범위 내에서 최소한의 변경으로 작업합니다.
- 기존 주석, docstring, 코딩 컨벤션을 훼손하지 않습니다.
- 불필요한 외부 패키지를 임의 설치하지 않습니다.
- `any` 타입 사용을 지양하고 구체적인 타입을 정의합니다.
- API 키, 시크릿 토큰 등 민감 정보는 절대 코드에 하드코딩하지 않고 환경변수(`.env.local`)로 분리합니다.

### 4. 사후 검증
- `tsc --noEmit` 및 `npm run lint` 에러 0건 확인
- 테스트 재실행하여 100% Pass 확인
- 요청받지 않은 파일의 불필요한 변경이 없는지 확인
- *(서브에이전트 병렬 작업 완료 후)* 메인 에이전트가 전체 통합 검증(타입, 린트, 테스트)을 최종 1회 일괄 수행합니다.

### 완료 보고
```
### ✅ 작업 완료 보고
#### 1. 변경된 파일
- `[수정/생성]` [파일명](file:///경로) - 변경 핵심 요약
#### 2. 검증 결과
- 타입 & 린트: 통과 ✅ | 테스트: [N]개 중 [N]개 통과 ✅
#### 3. 수동 확인 필요 사항 (있는 경우)
```
